# 开源机制溯源对照表

> 用途：说明本模块每一处能力来自哪个开源项目的哪一种机制，借鉴了什么、改写了什么。
> **合规红线**：本机其他目录的代码一律未复用。本文件记录的"借鉴"指**算法规则与公开定义**，
> 实现方式全部为纯 Python 独立重写，未 import、未 copy、未 fork 任何外部仓库代码。

| M2 | 防未来函数 / 反重绘闸门，walk-forward 截断重算是金标准 | 量化回测社区通用验证法 | `rdp/core/guard.py` | **升级为多切点对拍**（见下方"重要修正"） |
| M3 | 六维加权评分卡（25/20/20/15/10/10） | 本次 ChatGPT 比选对话产出的评分模型 | `rdp/core/scorecard.py` | 权重原样沿用，评分对象改为"本次诊断的可信度" |

## 二、B 类：必须重写为 Python 的算法（原项目多为 Pine Script）

| 引擎 | 借鉴的开源项目/机制 | 借了什么 | 改了什么（与原版的实质差异） |
|---|---|---|---|
| `volume_profile` | Volume Profile 类项目（价格分箱 + 量归属 + POC + 价值区间 70%） | 分箱规则、POC 定义、价值区间由 POC 向两侧累加到 70% | 固定 24 箱（未做波动率自适应）；滚动 60 根窗口；输出为 state 类信号 |
| `smc` | Smart Money Concepts 类项目（BOS / CHoCH / Order Block / FVG / 流动性扫单） | 摆动点突破定义 BOS/CHoCH；OB 取突破前最后一根反向 K 线；FVG 为三根 K 线真空区 | 摆动点改用自研对称分形 `swing_pivots(left=3,right=3)`；**OB 的识别延迟写成 `confirm_bars = i-j`**（见下方"重要修正"） |
| `divergence` | 背离类项目（常规背离 / 隐藏背离） | 顶背离=价更高 RSI 更低；底背离=价更低 RSI 更高；隐藏背离判延续 | 只用 RSI14（未纳入 MACD/量能交叉验证）；第二摆动点须右侧确认才转 confirmed |
| `pattern` | K 线形态与图表形态类项目 | doji / hammer / 看涨吞没 / 看跌吞没的量化阈值；双顶双底须破颈线才成立 | 未破颈线只记 candidate；等高匹配容差 5%（未做颈线有效性过滤） |
| `wyckoff` | Wyckoff 方法类项目 | 交易区间（Trading Range）划分；Spring / Upthrust 假突破；Effort vs Result 放量无果 | **区间边界严格取 `[i-50, i-1]`，不含第 i 根**（原版常把当前根算进边界，等于自我实现）；假突破延迟 2 根确认 |
| `dow` | 道氏理论类项目 | 依次抬高的高点+低点=上升趋势；次级折返 1/3~2/3；量能确认 | 摆动点换成自研分形；**每一组相邻摆动点都出信号**（原版只报最新一条，会让对拍失真） |

## 四、重要修正记录（本轮）

### 修正 1：防未来函数闸门原本是空转的
**问题**：`pipeline.build()` 先把 `bars` 截断到 as_of，再交给 `check_engine`，
于是"全量"与"截断"两边数据完全相同，体检恒为通过 —— 之前报的 196/196 是假象。

**修正**：
- `pipeline` 改为传入**未截断**的 `bars_all` 与 `as_of_idx`；
- `check_engine` 改为在 5 个历史切点（as_of 的 55%/70%/82%/92%/100%）上重算并对拍；
- 新增 `test_guard_is_not_vacuous` 断言切点数量，防止再次退化。

**效果**：修正后立即暴露 37 只标的的 SMC 订单块问题（见修正 2），证明闸门真的在工作。

### 修正 2：订单块的 confirm_bars 契约失真
**问题**：订单块位置在第 j 根，但要等第 i 根突破发生才被识别。原实现写
`confirm_bars=0`，等于宣称"第 j 根收盘就知道它是订单块"，对拍时在截断端必然报错。

**修正**：`confirm_bars = i - j`，`confirmed_idx = i`，证据里补 `identify_lag_bars`。
修正后 196/196 恢复全通过 —— 这回是真的全通过。

### 修正 3：引擎的 `[-N:]` 截断会破坏对拍
**问题**：`smc` 原只返回最后 6 条结构事件、4 条 FVG，`divergence` 只返回最后 5 条，
`pattern` 只返回最后 8 条 K 线信号。截断后"全量"里反而没有老信号，对拍必然不一致。

**修正**：引擎一律返回**完整历史**，展示条数交给报告层控制（HTML 详情卡限 8 条）。

### 修正 4：新增信号作用域 `scope`
- `event`：历史事件，形成于某一根具体 K 线，参与 walk-forward 对拍；
- `state`：当前状态量（筹码位置、Wyckoff 阶段、道氏阶段），天然依附最后一根 K 线，
  若参与对拍必误报，故排除，改为校验其 `formed_idx` 不越界。

## 五、当前体检口径（三条铁律）

1. 只比 `event` 类信号，`state` 类不比对拍；
2. 只比"已跨过确认窗"的信号：`formed_idx + confirm_bars <= 切点`；
3. 状态只允许单向推进：截断端是 candidate、全量端变 confirmed 合法；
   反过来（已确认退回候选）判为重绘，FAIL。
